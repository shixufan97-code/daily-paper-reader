## 摘要
对长且相互关联的文档进行问答（QA）仍然具有挑战性，因为相关证据可能跨越多个实体及其关系。现有的检索增强生成（RAG）方法通常将文档索引为原始文本块，并通过嵌入相似度进行检索。当文本块边界将实体与支持证据分离，或问题需要跨语料库的多跳推理时，其性能会下降。我们提出了EnSI-RAG（实体结构索引检索增强生成），一种构建查询无关的、以实体为中心的索引的框架。每条记录（e, t, k, v）表示一个实体e、其类型t、语义类别k（属于{属性，关系，方面}）以及值v，同时保留对原始来源段落的链接。在查询时，这些记录作为检索句柄，由LLM将检索到的段落综合成最终答案。这种设计将证据定位与答案综合分离，同时保留可溯源的证据。在Loong和Oolong上，EnSI-RAG实现了78.24的平均准确率。相对于用作参考的已发布基线分数，这一成绩高出6.62分，表明其在这些设置下的有效性。代码可在https://github.com/RamonMeng/EnSI-RAG获取。

## Abstract
Question answering (QA) over long, connected documents remains challenging because relevant evidence may span multiple entities and their relationships. Existing retrieval-augmented generation (RAG) methods typically index documents as raw chunks and retrieve them through embedding similarity. Their performance degrades when chunk boundaries separate entities from supporting evidence or when a question requires multi-hop reasoning across the corpus. We propose EnSI-RAG (Entity-Structure-Indexed Retrieval-Augmented Generation), a framework that constructs a query-independent, entity-centered index. Each record (e, t, k, v) represents an entity e, its type t, a semantic category k in {property, relation, aspect}, and a value v, while retaining links to the original source passages. At query time, these records serve as retrieval handles, and an LLM synthesizes the retrieved passages into the final answer. This design separates evidence localization from answer synthesis while preserving traceable source evidence. Across Loong and Oolong, EnSI-RAG achieves an average accuracy of 78.24. Relative to the published baseline scores used as references, this is 6.62 points higher, suggesting its effectiveness across these settings. The code is available at https://github.com/RamonMeng/EnSI-RAG.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题背景**：长文档问答（Long-Document QA）在金融、法律、学术等真实场景中非常常见，但所需证据往往分散在多个实体及其关系之中，难以通过单一段落定位。
- **现有方法不足**：
  - 直接扩展 LLM 上下文窗口无法解决证据利用问题，模型存在“lost in the middle”现象，对分布在不同位置的证据利用不均。
  - 传统 RAG 按固定长度切块（chunk）并通过嵌入相似度检索，块边界可能切断实体与证据、将无关内容混入同一检索单元，导致召回证据不完整或含噪；同时难以支持多跳推理和跨文档聚合。
- **核心思路**：将检索单元从“机械切块”改为“语义实体中心段落”，并构建查询无关的实体结构索引，用结构化记录作为检索句柄，最终仍由 LLM 基于原始证据段落生成答案。
- **整体含义**：通过分离“证据定位”与“答案合成”，在传统块式 RAG 与完全结构化数据库式问答之间提供一种灵活高效的中间方案。

## 2. 方法论：核心思想与关键技术细节

**整体框架**：EnSI-RAG 分为离线预处理（查询无关）和在线问答两个阶段。

### 2.1 离线预处理

- **Passage Construction（段落构建）**：
  - 将原始长文档转换为以主实体为中心的、语义自包含的段落（`P = {p1, ..., pm}`）。
  - 每个段落有稳定 ID（psg_id），保留来源文档、偏移量和结构化上下文（标题、表头、报告期等）。
  - 段落设计不采用全局固定 schema，而是根据任务和文档结构动态实例化，但下游接口统一。
- **Information Extraction（信息抽取）**：
  - 对每个段落抽取实体中心记录：`r = ⟨e, t, M, psg_id⟩`，其中 `e` 为实体，`t` 为类型，`M` 为语义字段集合。
  - 每个字段 `m = ⟨c, k, v⟩`，`c ∈ {property（属性）, relation（关系）, aspect（方面）}`。
  - 例如：属性 `birth-loc = Memphis`；关系 `cites = paper B`；方面 `method`、`legal reasoning` 等。
  - 抽取原则：① 每个字段必须由段落局部证据支持；② 抽取面向检索而非直接面向答案，即使部分记录不完整，只要指向正确证据即可。
- **Index Entry Building（索引条目构建）**：
  - 将记录映射为索引键：`[e][t][c: k = v] → { psg_id }`。
  - 索引是集合值（set-valued）：同一键可能对应多个段落，保留重复、矛盾、不同视角的证据，供生成时裁决。
  - 对关系同时建立反向条目（如 cites 与 cited-by），支持从关系任意一侧检索。
  - 同时保留符号字段和文本表示，支持精确匹配与语义匹配。

### 2.2 在线问答

- **Retrieval Planning（检索规划）**：
  - 将用户问题转换为检索计划 `H(q) = {h1, ..., hm}`，每个 hop 指定实体、类型、属性/关系/方面、目标值等组合。
  - 多跳问题中，前一跳的结果作为后一跳的中间实体或值。
- **Retrieval（检索）**：
  - 每个 hop 与索引键进行兼容性打分：`score(h, x) = Σ λ_a · s_a(h, x)`，涵盖实体、类型、类别、字段名、值等维度。
  - 支持部分约束（如只指定实体+关系，目标未知）。
  - 候选段落集合：`C_h = ∪ I(x)`，`C_q = ∪ C_h`，去重后可重排序。
  - 关键点：不依赖整体问题与匿名块的嵌入匹配，而是通过结构化实体键约束检索，实现多跳路径。
- **Generation（生成）**：
  - 直接使用原始检索段落和问题作为 LLM 输入：`ŷ = LLM(q, C_q)`。
  - LLM 仅负责理解与综合证据，不参与索引或符号推理，保证证据可溯源。

## 6. 主要结论与发现

- EnSI-RAG 在 Loong 和 Oolong 上平均准确率达到 78.24，显著优于传统 RAG、LongRAG、GraphRAG，且超过最强基线 SLIDERS 6.62 分。
- 实体中心段落比固定块更有利于检索和生成，行级粒度优于表级。
- 粗粒度语义标签并不总是优于细粒度，最佳粒度取决于领域（法律需要细粒度）。
- 检索深度并非越大越好，紧凑证据可减少干扰。
- 关键设计启示：证据定位（结构索引）与答案合成（LLM）分离，保留原始段落作为证据，能避免结构化提取错误直接污染推理，同时提高可追溯性。

## 7. 优点

- **方法创新**：提出以实体为中心的段落表示，取代固定长度块，语义连贯性好。
- **查询无关索引**：索引构建不依赖具体问题，可复用，支持任意未来查询。
- **结构仅作检索句柄**：结构化记录不替代原始文本，生成仍基于原始段落，避免信息丢失。
- **支持多跳与聚合**：关系双向索引和集合值保留多种证据路径。
- **泛化性强**：在各领域（金融、法律、论文）使用统一框架，并允许领域特定段落设计。
- **效率设计合理**：离线成本可摊销，在线只需 2 次 LLM 调用（检索规划+生成），延迟低。
- **可解释性与可审计性**：每个答案可追溯到原始段落。

- **应用限制**：主要针对问答场景，未评估开放式摘要、对话等其他 RAG 任务。
